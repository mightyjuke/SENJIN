# SENJIN Ember — Blender / Godot asset kit

This branch replaces the mobile prototype's runtime-built character and fortress placeholders with editable Blender sources and checked-in glTF 2.0 exports. Open `godot/project.godot`; the default scene now uses `scripts/art/native_main.gd`. Both iOS and Android use this same visual layer. The browser build and native battle rules are unchanged.

## Inventory

21 `.blend` sources in `art/blender/` and 21 `.glb` exports in `godot/assets/models/`:

| Group | Files |
|---|---|
| Rigged characters | `vanguard`, `soldier`, `officer` |
| Instanced distant crowd | `soldier_body`, `soldier_leg_l`, `soldier_leg_r` |
| Weapon | `polearm` |
| Modular environment | `wall`, `gate`, `tower`, `barricade`, `banner`, `tent`, `brazier`, `crate`, `rock`, `paver` |
| Effects | `slash_arc`, `shock_ring`, `spark`, `surge_ribbon` |

The art direction is faceted charcoal armor, weathered steel, crimson cloth and gold trim. Geometry, palette paint, rigging and keyframes are generated by the versioned Blender Python authoring script; the resulting meshes and actions can also be edited normally in Blender. This is a first authored low-poly kit, not hand-sculpted production art, a photoreal character pack, or a one-for-one reconstruction of the browser presentation.

## Rig and animation contract

Each detailed character has one mesh/material, an 18-bone skin and 23 separate actions: `Idle`, `Run`, `Dodge`, `Jump`, `Land`, `Hit`, `Death`, `n1`–`n6`, `c1`–`c6`, `dash`, `jatk`, `jc`, `Surge`. Combat clip lengths match the 60 Hz move definitions. `TrailBase` and `TrailTip` follow the weapon bone.

Animations are sampled by `AnimationPlayer` from simulation time, with short pose transitions. Root movement and damage remain in `battle.gd`; visual clips do not drive hit detection. This preserves hitstop, pause and gameplay timing. `Land` and `Death` are authored clips, but their full gameplay presentation still needs iteration.

Blender sources use metres, Z-up and -Y forward; glTF exports use Y-up and +Z forward. The Godot actor wrapper rotates +PI to match this game's -Z-facing simulation. Do not apply an extra axis conversion in an artist export. Static batch meshes must have identity node transforms. Do not rename the rig bones, actions or trail sockets without updating the integration and tests.

## Edit and export

Use Blender **5.2.0 LTS** and Godot **4.7.2** with matching export templates.

For normal art iteration, edit `art/blender/vanguard.blend`, save it, then run from the repo root:

```sh
blender -b --python art/tools/export_blend.py -- --root . --asset vanguard
python3 art/tools/verify_exports.py --refresh-manifest
godot --headless --path godot --editor --import --quit
godot --headless --path godot --script res://tests/assets.gd
```

Commit the edited `.blend`, `.glb`, import policy and refreshed manifest together. Keep vertex paint in the `Color` attribute, one material per asset and all action names. This exporter intentionally omits UV textures; extend the schema and importer before adding textured assets.

To regenerate the entire initial kit from scripted definitions:

```sh
blender -b --python art/tools/build_assets.py -- --root . --render
python3 art/tools/verify_exports.py
```

**Regeneration overwrites the named sources and exports. Do not run it over uncommitted or hand-edited Blender work.** Use `export_blend.py` for manual changes. `.blend1`, `.godot/`, preview-frame sequences and tool binaries are not repository assets.

The branch-only `Generate Blender asset kit` workflow performs this regeneration, validates the outputs, and commits only generated sources/exports/previews back to `art/blender-godot-pipeline` if its head has not moved. It never writes main. Once the art is hand-maintained, disable regeneration or change its trigger; read-only asset validation remains suitable for normal PRs.

## Runtime design and budgets

The hero and officers are skinned. At most eight nearby ordinary soldiers use skinned actors; the remainder use three low-poly MultiMesh parts. Their lower-detail silhouette and simpler gait are deliberate performance tradeoffs, not visual parity. Nearby slot ownership refreshes every 12 simulated frames. Static pavers are batched; other environment modules reuse imported meshes. No Blender executable is needed to open, export or run the checked-in Godot client.

Per-asset budgets: hero/officer under 6k triangles; soldier under 4k; distant body under 500 and each leg under 100; entire raw GLB pack under 8 MiB. Actual counts and SHA-256 hashes are generated into `manifest.json`. These are content budgets, not a measured phone FPS guarantee.

Imported vertex color is explicitly enabled. The post-import script converts linear glTF color data into sRGB vertex storage and sets the material's vertex-color flags, addressing the tested Compatibility-renderer washed-out-material issue. Static meshes receive generated LODs; skins retain their original arrays and named binds. Changing the renderer requires another visual check.

The visual layer uses imported effect meshes, additive sparks, a weapon-socket trail and a radial Surge effect. It is not a full particle/cloth/cinematic parity port. Props are decorative; the original circular battle boundary remains authoritative. Banners/flames are currently static meshes. Sound and HUD are largely retained from the native port.

## Validation

```sh
python3 art/tools/verify_exports.py
godot --headless --path godot --editor --import --quit
godot --headless --path godot --script res://tests/assets.gd
godot --headless --path godot --script res://tests/run.gd
godot --path godot --script res://tests/touch_ui.gd
godot --path godot --script res://tests/asset_visual.gd -- --capture=/tmp/characters.png
godot --path godot -- --smoke --touch --capture=/tmp/battle.png
```

Asset tests check mesh/rig/clip structure, vertex colors, finite poses, hashes, budgets, moving sockets, hitstop, crowd pooling and absence of render-side simulation mutation. Rendered previews are actual Blender or Godot output, not concept illustrations. Physical-device frame times, thermal behavior, crowd transition popping, extended animation review and final art direction still require acceptance before release.
